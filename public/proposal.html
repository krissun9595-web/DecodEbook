00 Design Direction

NETRUNNER'S
READING DECK

A cyberpunk visual identity for a bilingual reading & language‑learning engine. The chrome looks like a hacker's HUD — angular frames, corner brackets, tech readouts. The content stays calm and legible, because the whole point is to make hard books readable.

Every icon, frame, and control speaks the same language: read · listen · translate · learn. Reference tone: Cyberpunk 2077 UI art — HUD glyphs, hazard accents, monospaced data labels — retuned to DecodΞbook's neon palette.

01 Principles

Cyberpunk chrome, calm content

Six rules that keep the style bold without hurting reading.

P.01

Chrome vs. Content

HUD styling lives on toolbars, frames, buttons, chrome. The reading surface stays quiet — high contrast, generous spacing, no glow behind text.

P.02

Angular, not round

Boxes get chamfered corners (clip‑path), corner brackets, and notches — the 2077 "cut metal" feel — instead of soft radii.

P.03

Data readouts

Labels are monospaced, uppercase, tracked out — like scanner output. Numbers use tabular figures. Everything reads as telemetry.

P.04

Accent per system

Each module keeps its signature color (from the landing narrative) so the app feels like 7 subsystems of one deck.

P.05

Hazard = danger only

Yellow‑black hazard stripes are reserved for destructive / irreversible actions. Scarcity keeps them meaningful.

P.06

Language‑first icons

Every glyph encodes reading, listening, or translation — never generic media icons. The theme is the brand.

05 Frames & Boxes

Four surfaces, one HUD

A small kit replaces today's plain bordered boxes — each with a clear job.

01 · Data Slate

Chamfered content panel

Default surface for cards, players, panels. Cut corners + faint inner gradient. Replaces flat .content-panel.

02 · Bracket Frame

HUD corner target

For the active / focused module toolbar. Four accent brackets that adopt the system color. Evolves today's 2‑corner .hud-border.

03 · Hazard Header

Destructive zone

Yellow‑black stripe caps panels for irreversible actions (Clear cache, Delete book). Used sparingly.

04 · Status Slate

Live / stateful card

Glowing edge + status LED for anything "running" or "active" — generation in progress, the active book, live sessions.

05·B Surface Direction · Glass + Neon Glow

Frosted glass, glowing edges

An alternate (or layerable) treatment: translucent frosted‑glass panels that blur whatever's behind them, wrapped in a neon glow border. It reads as holographic HUD glass floating over the content — and it composes with the angular clips from the section above (chamfered frosted glass). Where it works

Toolbars, players, popovers, the account modal, floating context menus, tooltips, the sidebar over the reader — anything that sits on top of content and benefits from depth.

Reading guard

The reading surface stays solid & opaque — blur + glow behind body text hurts legibility and battery. Glass is for chrome; the page you read is calm. (Also: a non‑blur fallback for reduced‑transparency / older browsers.)

08 Rollout

How I'd ship it

Incrementally, one reviewable slice at a time — same cadence as Phases 0–6, no big‑bang rewrite.

  • V2.1  Icon set — ship the 12 custom SVGs as a component, swap module + primitive icons app‑wide (pure asset change, zero layout risk).
  • V2.2  Frame kit — add .slate / .bracket-frame / .hazard / .status-slate recipes; migrate .hud-panel & .content-panel to chamfered variants.
  • V2.3  Controls — extend .btn-action with the angular clip + breach/hazard for destructive actions; apply confirm patterns.
  • V2.4  Per‑module accenting — wire each system's signature color through its toolbar, then a landing‑page refresh to match.
  • GUARD  Reading surface untouched throughout — all changes are chrome. Reduced‑motion + contrast held to the Phase‑1 standard.
